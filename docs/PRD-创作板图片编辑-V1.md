# 创作板图片编辑 V1

> 文档状态：产品决策已收敛，待最终确认
> 日期：2026-08-31
> 修订日期：2026-09-01
> 项目：PicAgent 套图工作台
> 终端：桌面端

## 1. 产品目标与边界

在套图工作台的创作板中，为已生成图片提供可追溯的模型编辑工作流。设计师在图片编辑器中调整文字、区域和画布范围，将结构化操作与自然语言说明加入当前对话，再提交给生图模型。

本 PRD 只覆盖创作板编辑态，不改变成品展示板的只读定位。V1 不实现浏览器本地像素级最终合成，编辑结果由图片编辑模型生成。

## 2. V1 工具范围

左侧工具栏固定包含且仅包含以下 7 个工具：

1. 重新编辑
2. 再次生成
3. 添加文本
4. 改文字
5. 局部重绘
6. 消除笔
7. 扩图

V1 只实现以上 7 个工具，其他图片增强和画面调整能力不进入本版本工具栏、正式接口或验收项。

## 3. 页面与编辑会话

- 外层创作板展示父卡片、子卡片、连线、任务状态和图片版本。
- 内层图片编辑器展示来源图片、文字层、OCR 边界框、蒙版笔画及选择状态。
- 右侧为当前工具参数面板，底部提供操作摘要和“添加到对话”。
- 图片编辑器使用接近全屏的固定布局；浏览器 100% 缩放时顶部、中央画布和固定底部操作区必须同时可见。左右面板独立滚动，中央图片始终完整 `contain` 显示。
- 一次编辑会话允许组合多个操作，例如添加文本、局部重绘和扩图。
- 每个操作拥有独立 `operationId` 和顺序；多个操作可以共同加入一次对话提交，但一次提交只生成一张子卡片。

## 4. 工具行为

### 4.1 重新编辑

- 展示设计师实际打开的来源图片版本在生成时冻结的完整版本生成提示词，不使用可能已经变化的任务卡当前提示词。
- 支持修改、追加和删除提示词。
- 添加到对话时记录来源版本和提示词修改说明。
- 提交时冻结为结构化 `EditSnapshot`，创建一张子卡片。
- 修改后的提示词只属于新子卡片，不覆盖来源版本及其历史提示词快照。

### 4.2 再次生成

- 只在同一卡片下新增一个图片版本，不创建子卡片。
- 默认使用 `currentVersionId` 对应的图片、当前任务提示词和当前生成参数。
- 如果设计师先将历史版本设为当前版，则从该历史版本开始。
- 没有当前版本时，才回退到任务原始输入图或白底图。
- Provider 不支持以当前版本作为来源时，必须在请求前阻止，不得静默退化。

### 4.3 添加文本

- 在画布中新增带虚线边框和变换手柄的文字区域，支持选择、移动、缩放、旋转和删除。
- 右侧只维护精确文字内容和该文字区域独立的操作提示词；V1 不提供字体、字号、颜色或文字效果控件。
- 一个文字区域对应一个独立 `operationId`；同一图片可以创建多个文字区域，选中已有文字区域后继续调整表示更新原操作。
- 文字区域必须保持在来源图片范围内，并保存精确文字、归一化位置、尺寸、旋转角度和操作提示词。
- 只有原图中不存在的新文字使用此工具；提交后创建子卡片。

### 4.4 改文字

- 打开工具后先调用独立 `OcrProvider` 识别文字。
- OCR 成功时保存精确 `sourceVersionId`、原文字、置信度、边界框和旋转信息；设计师选择文字块并人工修改。
- OCR 文字区域使用与添加文本相同的虚线选框和变换交互，允许人工校正位置、尺寸和旋转。
- 改文字保存独立的替换要求；默认要求为保持原有排版、字体感觉、颜色、透视和光影，只替换文字内容。
- 提交时保存原文字、新文字、区域、旋转信息和操作说明，创建子卡片。
- OCR 失败时仍保持 `change_text` 操作，允许重新识别或手工框选原文字区域；不得自动转换为 `add_text`，不得用叠加新文字冒充改字成功。

### 4.5 局部重绘

- 设计师使用画笔涂抹需要重绘的区域，支持笔刷大小、撤销、重做、清空和重新绘制。
- 画笔提供与实际笔刷大小一致的圆形指针，并提供“绘制选区”和“擦除选区”两种蒙版修正模式。
- 每个局部重绘操作维护独立且必填的重绘要求；提交时保存笔画快照、mask PNG、来源版本和操作提示词，创建子卡片。

### 4.6 消除笔

- 交互方式与局部重绘相同，先涂抹要移除的区域。
- 消除笔维护独立的清除要求，默认值为“移除选区中的目标，并根据周围画面自然补全背景，保持原有光线、纹理和透视关系”，允许设计师修改。
- 提交时保存笔画快照、mask PNG、来源版本和清除要求，创建子卡片。

### 4.7 扩图

- V1 支持方向：四周、左右、上下、向左、向右。
- V1 支持目标比例：原比例、1:1、3:4、4:3、9:16、16:9。
- 画布外侧使用透明棋盘格显示待扩展区域。
- 扩展量按目标比例自动计算，保持原图中心或指定方向锚点；不开放任意像素输入。
- 目标比例与方向冲突时，以目标比例作为最终尺寸约束。
- 提交时保存方向、目标比例、计算后的目标宽高、锚点和对话说明；结果创建子卡片。

## 5. 编辑器草稿与“添加到对话”

生命周期固定为：

`编辑器草稿 → 添加到对话 → 可继续更新或移除 → 点击生成时冻结 EditSnapshot → 创建 operation、child task 和 generation attempt`

规则：

- 点击“添加到对话”时不立即生成不可变快照。
- 已加入对话的操作继续绑定对应编辑器草稿；移动文字、调整蒙版或修改参数时同步更新。
- 重复点击同一操作更新原操作，不重复追加。
- 用户可以从对话中移除某项操作。
- 点击生成时才冻结完整、不可变的 `EditSnapshot`。
- 自然语言摘要允许修改，但不能覆盖或删除机器可读的操作类型、来源版本、坐标、蒙版和参数。
- 结构化操作失效或缺少必需数据时必须阻止生成，并提示缺失项。
- 添加文本缺少精确文字、有效文字区域或操作提示词时，局部重绘缺少有效蒙版或重绘要求时，消除笔缺少有效蒙版时，改文字缺少原文字、新文字或有效区域时，必须阻止加入对话。
- 弹窗底部固定展示已加入操作数量，以及取消、添加/更新对话操作和最终生成按钮；切换工具不清除已加入的其他操作。
- 保存草稿或提交失败时保留文字、蒙版、坐标和提示词；重新打开编辑器时恢复尚未提交的草稿。

一次冻结的 `EditSnapshot` 对应一个 child task 和一张子卡片，即使其中包含多个有顺序的编辑操作。不得只保存合并后的自然语言提示词。子卡片至少展示来源卡片、来源版本、操作摘要和生成状态。

## 6. 坐标与蒙版契约

- 所有持久化坐标以来源图片版本为唯一基准，原点为来源图片左上角。
- `x`、`y`、`width`、`height` 使用 `0..1` 归一化坐标。
- 笔刷宽度相对于来源图片短边归一化。
- 浏览器画布的缩放、平移及 `contain/cover` 仅是显示变换；提交前必须逆变换回来源图片坐标。
- Konva 覆盖层必须使用与来源图片实际显示区域一致的显示坐标变换；窗口尺寸、工具面板或图片布局变化后重新测量显示区域。
- 禁止保存浏览器视口坐标。
- 文字旋转以文字区域中心为旋转中心。
- 扩图生成后，后续编辑使用新图片版本的新坐标系。

mask PNG 契约：

- 尺寸与来源图片版本完全相同。
- 使用单通道灰度图；黑色表示不编辑区域，白色表示编辑区域。
- 边缘羽化参数必须进入 `EditSnapshot`。
- 数据库保存框架无关的归一化笔画；MinIO 保存生成后的 mask PNG、哈希、尺寸和 MIME。

## 7. 当前版与最终版

每张任务卡独立维护 `currentVersionId` 和 `finalVersionId`：

1. 首次成功版本自动成为当前版，但不自动成为最终版。
2. 最终版必须由设计师明确选择。
3. 再次生成成功后自动成为当前版，不清除原最终版。
4. 未设置最终版时，成品展示板回退显示当前版。
5. 失败或生成中的结果不能设为最终版。
6. 父卡片和子卡片分别维护自己的当前版和最终版。
7. 从历史版本发起编辑时，`parentVersionId` 必须指向设计师实际打开的版本。
8. 切换最终版只改变选择关系，不复制或删除图片对象。

## 8. 子卡片、失败、重试与幂等

编辑提交先完成能力检查，再使用一个事务创建：

- `EditOperation` / 冻结的 `EditSnapshot`；
- child task；
- first generation attempt。

规则：

- 子卡片在提交时创建，不等待模型成功。
- 失败子卡片必须保留并展示错误；失败不创建伪造 image version。
- 重试复用相同 child task 和 `EditSnapshot`，只追加 generation attempt。
- 成功后才在 child task 下创建 image version。
- 同一幂等键重复提交必须返回原 operation 和 child task，不得创建重复子卡片。
- 一次提交对应一个 child task、一个冻结 `EditSnapshot` 和一个或多个 attempts。

## 9. Provider 能力边界

能力矩阵：

| Provider | V1 能力 |
| --- | --- |
| `OcrProvider` | OCR 识别、OCR 重试、OCR 快照 |
| `ImageEditProvider` | 普通图生图、mask 局部重绘、消除、精确改字、添加文字、扩图 |

- 打开工具时显示能力状态，点击生成前再次检查能力。
- 不支持的能力必须明确阻止生成；能力检查失败时不创建 child task 和 attempt。
- 禁止把不支持的 mask、文字区域或扩图参数静默拼接成普通 prompt。
- Provider 和 capability 版本必须写入生成快照。
- 业务层负责生成稳定的 `ImageEditCommand`，Provider 负责将其转换为供应商请求。

## 10. 验收标准

1. PRD 状态为“产品决策已收敛，待最终确认”，只有用户明确说“PRD 确认，开始开发工作台”后才可进入正式开发闸门。
2. 左侧工具栏只包含 7 个 V1 工具，其他图片增强和画面调整能力不属于本版本。
3. 组合操作只生成一张子卡片，每个操作有独立 `operationId`。
4. “添加到对话”与生成时冻结 `EditSnapshot` 的生命周期可验证，支持更新、移除和失效阻止。
5. 坐标、逆变换、文字旋转中心及 mask PNG 契约可验证。
6. 当前版、最终版及父子卡片状态转换完整，失败/生成中结果不能成为最终版。
7. 子卡片提交、失败保留、重试和幂等规则可验证。
8. 改文字先 OCR；OCR 失败不会自动转成添加文本。
9. 再次生成从当前版开始，只新增同一卡片版本。
10. Provider 不支持时阻止请求，不静默降级。
11. XYFlow 与 Konva 的职责清晰，持久化只保存框架无关的 `EditSnapshot`。
12. 浏览器 80%、100%、125% 缩放下，横图、竖图和方图的笔刷圆心与实际落笔中心误差不超过 2 个 CSS 像素。
13. `1176×768`、`1280×720`、`1440×900` 可视区域下，图片编辑器底部操作区完整可见。
14. 每个生成图片版本显示其冻结的完整版本生成提示词；重新编辑不会覆盖来源版本快照。
15. 多个文字区域可独立选择、移动、缩放、旋转、删除并恢复草稿。

## 11. 不在范围与开发闸门

- 其他图片增强和画面调整能力；
- 浏览器本地像素级最终合成；
- 移动端编辑、多人实时协同、复杂图层混合和滤镜市场；
- 直接发布到电商平台。

本 PRD 当前尚未通过正式开发闸门。只有用户明确说“PRD 确认，开始开发工作台”后，才能开始或继续正式编码。
