# PicAgent 风格库（工作台资源库）V1 实现规格

> 规格状态：核心 V1 已实现；`reverse_prompt` 兼容扩展待开发
> 基于：PRD-风格库-工作台资源库-V1、原型评审结论、Ticket 07
> 日期：2026-08-31
> 主测试切缝：资源库应用服务/API

## Problem Statement

当前套图工作台已有“风格库”入口和原型页面，但真实业务资源尚未形成统一的查询、选择和追溯闭环。提示词模板位于既有模板版本模型中，原图、白底图、生成图和过程图位于套图业务对象中，设计师无法从一个工作台页面完成搜索、预览、查看完整生成提示词、引用到计划或任务，以及在后续变更后保持历史稳定。

## Solution

在 PicAgent 主应用内提供独立风格库资源页，以一个资源库应用服务/API 作为主要业务切缝；套图工作台仅通过资源引用消费资源：

1. 聚合已存在的提示词模板、输入图、底图版本、任务图片版本、过程对象和爆品图反推资产。
2. 负责资源筛选、可见性、模板阶段匹配、状态限制、引用幂等、引用快照和归档规则。
3. 前端沿用当前三栏原型：左侧筛选、中间列表、右侧详情。
4. 不复制图片文件、模板正文或 RAG 商品资料。
5. 现有模板版本、PlanSnapshot、SuiteTask、TaskImageVersion 和 MinIO 对象关系继续作为事实来源。

## User Stories

1. As a 设计师, I want to 从工作台打开风格库, so that 我不离开当前套图流程即可选择资源。
2. As a 设计师, I want to 默认看到图片资产, so that 我可以先处理商品图和生成图。
3. As a 设计师, I want to 切换到提示词模板 Tab, so that 我可以按执行阶段选择模板。
4. As a 设计师, I want to 按类型、状态、平台、品类和搜索词筛选, so that 我可以快速找到目标资源。
5. As a 设计师, I want to 看到资源卡的版本、引用次数和提示词关联状态, so that 我可以判断资源是否可复用。
6. As a 设计师, I want to 查看资源详情、预览、来源和引用关系, so that 我可以在选择前核对资源。
7. As a 设计师, I want to 看到非实拍图生成时的完整提示词和模板版本, so that 我可以复用和审查实际生成依据。
8. As a 设计师, I want to 看到实拍原图“不适用生成提示词”, so that 我不会误认为原图缺少生成数据。
9. As a 设计师, I want to 为计划选择一个已发布 plan 模板, so that 我可以生成套图计划。
10. As a 设计师, I want to 为单卡任务选择一个已发布 task_image 模板, so that 我可以生成单张图片。
11. As a 设计师, I want to 多选和排序参考图片, so that 我可以表达参考优先级。
12. As a 设计师, I want to 选择资源后不立即生成图片, so that 我可以继续检查输入。
13. As a 设计师, I want to 选择资源时不覆盖手写核心提示词, so that 人工修改不会丢失。
14. As a 设计师, I want to 刷新工作台后恢复已选引用, so that 资源选择不依赖临时浏览器状态。
15. As a 设计师, I want to 看到过程图但不能默认把它作为生成输入, so that 不稳定中间结果不会误入新任务。
16. As a 设计师, I want to 上传外部图片为草稿并在确认后发布, so that 我可以先整理资源再开放复用。
17. As a 设计师, I want to 让白底图、生成图、过程图和终版图在生产成功后自动进入资源库, so that 不需要重复保存。
18. As a 设计师, I want to 明确保存爆品图反推结果, so that 临时分析不会自动污染资源库。
19. As a 设计师, I want to 保存爆品图反推提示词和视觉结构, so that 后续可以复用构图、背景、光影、材质和道具方法。
20. As a 系统, I want to 阻止未经核验的品牌、参数、认证、功效、价格和销量进入反推商品提示词, so that 视觉参考不会变成虚假商品信息。
21. As a 模板维护人员, I want to 编辑 System Prompt、User Prompt Template、inputSchema 和 outputSchema, so that 模板规则和动态字段可维护。
22. As a 模板维护人员, I want to 复制已发布版本为新草稿, so that 修改不会破坏历史。
23. As a 模板维护人员, I want to 发布和下线模板版本, so that 运行时只使用明确可用的版本。
24. As a 系统, I want to 冻结资源版本和提示词快照, so that 后续更新不会改写历史计划、任务或图片。
25. As a 系统, I want to 对引用请求做幂等处理, so that 网络重试不会产生重复引用。
26. As a 系统, I want to 在预览失败时保留引用关系, so that 临时对象故障不会造成业务数据丢失。
27. As a 运营人员, I want to 查看引用次数和来源, so that 我可以发现高复用资源和历史依赖。
28. As a 系统, I want to 拒绝不属于当前方案可见范围的资源, so that 资源归属和数据隔离保持正确。

## Implementation Decisions

### 1. 主模块与业务切缝

- 新增或完善资源库应用服务，统一负责资源查询、详情、预览、引用和状态规则。
- 前端只通过该服务读取真实数据，不读取原型静态数组、fixture 或 localStorage 作为业务真相。
- PostgreSQL repository 负责资源聚合和引用持久化；MinIO adapter 负责对象读取和短期预览。
- 既有提示词、计划、任务和图片版本 repository 保留原职责。

### 2. 资源聚合

统一资源投影至少包含：

- 资源 ID、类型、标题、摘要；
- mime 类型和预览地址；
- 套图方案、任务、底图版本、任务图片版本和模板版本关联；
- 阶段、来源摘要、创建时间和更新时间；
- 提示词摘要、标签、平台和品类（存在时）。

资源类型至少包括：

- prompt_template
- input_image
- base_image
- task_image_version
- process_image
- reverse_reference_asset

资源库不复制源图片和模板正文；列表返回摘要，详情返回允许展示的完整快照。

### 3. 可见性和状态

- 运行时模板仅允许已发布版本。
- 计划目标只能引用 plan 模板；任务目标只能引用 task_image 模板。
- base_refine 模板继续由底图精修流程使用。
- 图片资产使用 draft、published、archived 三态。
- 草稿和归档图片不可新增引用；历史引用可读取。
- 过程图可查看和追溯，但默认不能作为常规生成输入。
- 归属特定方案的资源只能在允许的方案范围内读取。

### 4. 引用和快照

引用必须保存套图方案 ID、资源 ID、资源类型、目标类型、目标 ID、资源版本 ID、选择时的标题/类型/来源/模板版本摘要/必要提示词文本、幂等键、创建时间、创建者和归档时间。

规则：

- 同一资源不能重复绑定同一目标；
- 相同幂等键重试返回原引用；
- 引用快照不可更新；
- 归档引用只标记归档，不删除源资源；
- 提交计划或任务时再次冻结引用快照到 PlanSnapshot、TaskGenerationAttempt 或 TaskImageVersion。

### 5. 模板版本管理

- 沿用现有模板和模板版本模型。
- 草稿可修改，发布后正文、System Prompt、User Prompt Template、Schema、阶段和适用范围不可原地修改。
- 修改通过复制生成新版本。
- 同一模板最多一个已发布版本。
- 下线影响未来选择，不影响历史快照。
- 新增独立 `reverse_prompt` 阶段作为加法扩展，并复用现有模板版本、发布和查询机制。
- `reverse_prompt` 必须声明 `targetType=main|detail`；`base_refine`、`plan`、`task_image` 不得用于爆品图反推。

### 6. 图片归档

- 实拍原图沿用现有上传流程进入资源库。
- 白底底图、AI 生成结果、过程图和终版图在业务生成成功且对象写入 MinIO 后自动可查询。
- 外部非实拍参考图先进入草稿。
- 爆品图反推资产由用户确认保存后创建不可变资源记录，包含参考图、反推提示词、视觉结构、来源和模板版本。
- 爆品图反推不得把未经核验商品事实作为可复用商品事实。

### 7. API 外部契约

应用服务至少提供：

- 分页查询资源：类型、阶段、方案、搜索、状态和分页；
- 查询资源详情：版本、来源、引用关系、提示词快照和预览；
- 预览资源：归属校验后返回代理或短期地址；
- 查询已发布模板：支持阶段过滤；
- 创建资源引用：计划/任务目标、资源版本和幂等键；
- 查询目标引用：按方案、目标类型和目标 ID 恢复；
- 归档引用：不删除源资源。

统一响应为成功 data/requestId，失败 error/requestId；写请求支持 Idempotency-Key。

错误语义至少包括资源不存在或版本无效、资源归属不允许、模板阶段不匹配、计划或任务不存在、预览对象暂时不可用。

### 8. 前端交互

- 默认打开图片资产 Tab。
- 左侧筛选、中间列表、右侧详情沿用原型信息架构。
- 选择动作提示不会立即生成图片，并把引用状态反映到工作台。
- 选择资源不覆盖用户已经填写的核心提示词。
- 模板 Tab 按资源类型显示选择模板、查看版本和管理模板操作。
- 非实拍图片必须展示提示词快照；缺失快照显示数据异常。
- 图片预览失败显示可重试状态，不伪造资源可用。

### 9. 兼容性

- 不改变 base_refine、plan、task_image 的阶段语义。
- reverse_prompt 只服务爆品图反推，不扩大既有阶段的运行目标或目标类型。
- 不改变 inputSchema 驱动的动态表单。
- 不改写已存在的 PlanSnapshot、SuiteTask、TaskGenerationAttempt 和 TaskImageVersion。
- 不改变 N→N 首图、单卡一次一张、图片版本选择和 XYFlow 状态规则。
- 平台维护表和 System Prompt 优先于视觉参考。
- PicAgent 仍只读使用 RAG，不维护 RAG 商品资料。

## Testing Decisions

### 1. 原则

测试外部业务行为和接口契约，不测试 SQL 写法、React 内部状态变量或组件实现细节。优先在资源库应用服务/API 边界测试；需要数据库或对象存储行为时使用现有 fake 或独立测试实例。

### 2. 应用服务/API

覆盖资源类型、阶段、状态、搜索、分页、已发布模板过滤、目标阶段匹配、过程图不可选、方案归属校验、资源/目标不存在、引用幂等、快照不可变、归档资源拒绝新引用、历史引用读取和 MinIO 预览失败。

### 3. 模板版本

覆盖草稿编辑、复制版本、发布、下线、已发布版本不可修改、同一模板最多一个已发布版本，以及历史快照仍指向原模板版本。

### 4. 浏览器验收

桌面端验证：从工作台打开资源库、默认图片 Tab、搜索和筛选、查看图片详情和提示词、查看实拍原图提示、切换模板 Tab、选择模板和图片、返回工作台、刷新恢复、移除引用、归档和预览失败重试。

### 5. 回归

必须继续通过现有提示词模板契约、PlanSnapshot、套图任务/图片版本/画布恢复测试，以及 TypeScript 类型检查、生产构建和桌面浏览器验收。

## Out of Scope

- 独立风格库后台；
- 多租户、权限角色、多人协作和复杂审批；
- 风格实体、片段组合、相似度推荐、自动训练和公开分享；
- RAG 商品资料维护、Chunk 编辑、事实审核和入库；
- 自动从参考图生成完整商品事实；
- 移动端和在线图片编辑器；
- 直接发布到电商平台；
- 修改现有图像生成 provider、任务状态机或 XYFlow 画布业务真相。

## Further Notes

1. 当前原型是信息架构和交互基线，不是视觉定稿；实现应复用工作台现有 UI 组件和样式。
2. “风格库”是产品入口名称，V1 实际领域对象是提示词模板和图片资产。
3. 非实拍图的提示词展示必须基于生成时快照，不得读取模板当前正文冒充历史记录。
4. 资源库不拥有图片版本真相；图片业务版本继续由套图业务模型负责。
5. `reverse_prompt` 是已确认的加法阶段扩展；实现必须补充阶段隔离、历史模板兼容和浏览器筛选回归测试。其他阶段枚举或计划快照变更仍需单独确认。
6. 推荐实现顺序：应用服务契约测试 → 真实资源聚合 → 引用持久化与快照 → 工作台入口接入 → 模板/图片管理动作 → 浏览器验收。
7. 当前仓库远程为 Gitee，环境中未发现可直接发布本规格到 issue tracker 的已配置工具；本文件是本地可审阅规格，需由项目维护流程另行创建 issue。
