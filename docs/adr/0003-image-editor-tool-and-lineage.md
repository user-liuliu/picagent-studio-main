# ADR 0003：创作板图片编辑器与子卡片血缘

- 状态：Proposed，待最终确认
- 日期：2026-08-31
- 修订日期：2026-09-01

## 背景

套图工作台需要在创作板中支持重新编辑、再次生成、添加文本、改文字、局部重绘、消除笔和扩图。外层工作台使用 XYFlow 表达任务卡关系，但 XYFlow 不负责图片编辑画布、笔刷、文字变换或 OCR 框选。本 ADR 记录已收敛、待最终确认的架构决策。

## 决策

### 1. 双层画布职责

- 外层创作板采用 XYFlow，负责父卡片和子卡片、连线、任务状态、图片版本展示和画布布局。
- 内层图片编辑器采用 Konva + react-konva，负责图片显示、文字层、OCR 边界框、蒙版笔画、拖拽、缩放、旋转、撤销、重做和编辑预览。
- 内层编辑器不替换 XYFlow，也不把图片编辑节点直接建模成 XYFlow 节点。
- Konva 是 V1 的明确采用方案；替换为 Fabric.js 或原生 Canvas 时，历史业务快照仍必须可读取。

### 2. 画布无关的编辑模型

业务层以 `EditOperation` 和不可变 `EditSnapshot` 作为唯一持久化模型。`EditSnapshot` 至少包含：有序操作及其 `operationId`、来源卡片/来源版本、自然语言说明、归一化区域、归一化笔画、文字/OCR 数据、扩图参数、羽化参数、Provider 与 capability 版本。

- API 和数据库只保存框架无关的 `EditSnapshot`。
- 禁止保存 Konva Stage JSON、Konva 私有类型或节点 ID。
- 浏览器中的 scene graph 只是可变草稿和预览；点击生成时才把草稿冻结成 `EditSnapshot`。
- 业务层负责生成稳定的 `ImageEditCommand`，Provider 只负责将命令转换为供应商请求。
- `ImageEditCommand` 的提示词由来源版本冻结的完整提示词、按顺序排列的结构化操作和各操作独立提示词组成。来源版本提示词不能从任务卡当前可变提示词推断。

### 3. 编辑会话、组合操作与对话生命周期

编辑会话允许组合多个有顺序的操作，一次提交只对应一个 `EditSnapshot`、一个 child task、一张子卡片和一个或多个 generation attempts。

生命周期为：

`编辑器草稿 → 添加到对话 → 可继续更新或移除 → 生成时冻结 EditSnapshot → 创建 operation、child task 和 attempt`

- 点击“添加到对话”不创建不可变快照；操作继续绑定编辑器草稿。
- 移动文字、调整蒙版或修改参数时，同一 `operationId` 的对话项同步更新。
- 重复点击同一操作执行更新，不重复追加。
- 一个文字区域是一个独立文字编辑操作；同一编辑会话可以包含多个文字区域和多个独立 `operationId`。
- 自然语言摘要可编辑，但不能覆盖或删除机器可读字段。
- 结构化操作失效或缺少必需数据时，生成前阻止提交。

### 4. 子卡片血缘、事务、失败与幂等

除再次生成外的所有语义编辑都创建子卡片。提交前先完成能力检查；通过后在一个事务中创建 `EditOperation`、冻结的 `EditSnapshot`、child task 和 first generation attempt。子卡片在提交时创建，不等待模型成功。

- child task 保存来源卡片、实际打开的来源版本、操作摘要、冻结快照和生成状态。
- 失败子卡片保留并展示错误；失败不创建伪造 image version。
- 重试复用相同 child task 和 `EditSnapshot`，只追加 generation attempt。
- 成功后才在 child task 下创建 image version。
- 同一幂等键重复提交返回原 operation 和 child task，不创建重复子卡片。
- 父卡片与子卡片分别维护 `currentVersionId` 和 `finalVersionId`。

### 5. 坐标与 mask PNG 契约

所有持久化坐标以来源图片版本为唯一基准，原点为来源图片左上角。矩形的 `x`、`y`、`width`、`height` 使用 `0..1` 归一化；笔刷宽度相对于来源图片短边归一化。浏览器的缩放、平移和 `contain/cover` 只是显示变换，提交前必须逆变换回来源图片坐标，禁止保存视口坐标。文字旋转中心为文字区域中心；扩图生成后，后续编辑切换到新图片版本的新坐标系。

Konva Stage、文字变换框和蒙版画笔必须共享来源图片在浏览器中的实际显示矩形。实现可以使用显示尺寸渲染并保存归一化结果，或使用一致的画布缩放和逆变换，但不得只缩放 Stage 外层容器而保留内部 Canvas 的来源像素尺寸。图片或面板布局变化时必须重新测量显示矩形。

mask PNG 的框架无关契约为：

- 尺寸与来源图片版本完全相同；
- 单通道灰度图；黑色表示不编辑区域，白色表示编辑区域；
- 边缘羽化参数进入 `EditSnapshot`；
- 数据库保存归一化笔画；MinIO 保存生成后的 mask PNG、哈希、尺寸和 MIME。
- “擦除选区”只修改当前蒙版，不等于要求模型移除图片内容的“消除笔”。

### 6. 当前版与最终版

每个任务卡独立维护 `currentVersionId` 与 `finalVersionId`：

1. 首次成功版本自动成为当前版，但不自动成为最终版。
2. 再次生成成功后自动成为当前版，不清除原最终版。
3. 未设置最终版时，成品展示板回退显示当前版。
4. 失败或生成中的版本不可设为最终版。
5. 从历史版本发起编辑时，`parentVersionId` 指向设计师实际打开的版本。
6. 切换最终版只改变选择关系，不复制或删除图片对象。

再次生成只在同一卡片下新增一个 image version：默认从当前版图片、当前任务提示词和当前生成参数开始；没有当前版才回退到原始输入图或白底图。`finalVersionId` 仅表示交付选择，不自动成为再次生成输入。Provider 不支持当前版本作为来源时，生成前阻止请求。

### 7. OCR 与改文字边界

OCR 使用独立 `OcrProvider`，能力包括 OCR 识别、OCR 重试和 OCR 快照。OCR 快照必须绑定精确 `sourceVersionId`，并保存识别文字、置信度、边界框和旋转信息。

- `change_text` 先 OCR，再由设计师选择文字块并修改。
- `change_text` 与 `add_text` 使用相同的文字区域变换模型；精确文字和归一化区域是结构化数据，文字视觉要求保存在独立操作提示词中。
- OCR 失败时保持 `change_text`，允许重新识别或手工框选原文字区域。
- OCR 失败不得自动转换为 `add_text`，不得用叠加新文字冒充改字成功。
- 只有原图不存在的新文字才使用 `add_text`。

### 8. Provider 能力矩阵与拒绝策略

| Provider | 能力 |
| --- | --- |
| `OcrProvider` | OCR 识别、OCR 重试、OCR 快照 |
| `ImageEditProvider` | 普通图生图、mask 局部重绘、消除、精确改字、添加文字、扩图 |

- 打开工具时显示能力状态，点击生成前再次检查能力。
- 不支持的能力必须明确阻止生成；能力检查失败时不创建 child task 和 attempt。
- 禁止把不支持的 mask、文字区域或扩图参数静默拼接成普通 prompt。
- Provider 名称、Provider 版本和 capability 版本写入生成快照。
- Provider 适配层只接收稳定的 `ImageEditCommand`，不让业务层依赖供应商私有字段。

### 9. 扩图约束

扩图 V1 只支持四周、左右、上下、向左、向右，以及原比例、1:1、3:4、4:3、9:16、16:9。系统自动根据目标比例计算扩展量，保存方向、目标比例、计算后的目标宽高、锚点和对话说明；不开放任意像素输入。方向与比例冲突时，以目标比例作为最终尺寸约束。扩图结果创建子卡片。

## 结果与代价

- 需要新增正式的编辑操作、不可变快照、子任务血缘和 generation attempt 记录；现有 `generationParams.editSpec` 只能作为兼容字段，不能承担完整历史。
- 需要在数据库与 MinIO 之间保存结构化笔画和生成后的 mask PNG，并维护哈希、尺寸、MIME 与来源版本。
- 需要增加 Provider capability 检查、拒绝路径、OCR 服务边界和幂等重试语义。
- Konva 能降低内层 2D 编辑实现复杂度，但会引入 scene graph 适配成本；通过只持久化 `EditSnapshot` 将替换成本限制在编辑器适配层。
- 失败子卡片和不可变快照会增加记录数量，但换取可审计、可重试和可比较的生成血缘。
- 详细 API、数据库字段和迁移方案不在本 ADR 内；只有通过正式开发闸门后，才能按实现计划在 TECH-SPEC 和代码中落地。

## 放弃的方案

### 直接在 XYFlow 卡片上绘制蒙版

放弃。XYFlow 适合节点和连线编排，不适合作为图片像素编辑器，容易把任务关系与编辑状态耦合。

### 只把编辑说明拼接进提示词

放弃。自然语言无法可靠表达位置、蒙版、OCR 框、文字层、扩图约束和父版本关系，也无法支撑稳定的操作重放。

### 浏览器本地直接合成最终图

放弃。V1 的编辑动作最终交给生图模型，浏览器只负责编辑上下文和预览，不把本地合成结果冒充模型生成版本。

### Provider 不支持时静默降级为普通图生图

放弃。静默降级会丢失结构化编辑语义并产生不可预测结果；应在能力检查阶段明确阻止生成。

## 开发闸门

本 ADR 当前尚未通过正式开发闸门。只有用户明确说“PRD 确认，开始开发工作台”后，才能开始或继续正式编码；实现必须继续遵守本文的双层画布、框架无关快照、子卡片血缘、版本选择和 Provider 能力边界。
