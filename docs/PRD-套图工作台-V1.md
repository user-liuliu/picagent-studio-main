# PRD-套图工作台-V1

> 文档状态：最终版，已确认，可进入开发
> 版本：V1.0
> 日期：2026-08-22
> 项目：PicAgent 套图工作台独立项目
> 终端：桌面端

本文档是套图工作台独立 PRD，不引用旧项目总 PRD。套图以外的模式和后续数据中台能力，分别新建 PRD。

## 1. 产品目标

把 1–6 张商品原始实拍图处理为：

1. 与原图一一对应的精修白底图；
2. 由 LLM 生成并可人工修订的套图图片计划；
3. 每个图片任务一张首图的套图卡片集合；
4. 支持单卡精修、历史版本对比、重新选择当前图和终版图的可追溯工作流。

首版只追求工作台主流程可用，不建设完整商品资料维护、审核平台或移动端。

## 2. V1 范围

### 2.1 必须实现

- 创建、保存、刷新恢复和继续处理套图方案；
- 上传 1–6 张任务输入图；
- 顶部缩略图横条切换原图；
- 原图与对应白底精修图对齐展示；
- 设计师点击生成后才调用白底精修；
- 白底图重复生成保留历史版本并可切换当前版本；
- 按阶段选择提示词模板；
- 根据模板展示动态输入项；
- 设计师检索并勾选 RAG Chunk；
- 使用现有 RAG 能力和项目 DashScope LLM 生成结构化图片计划；
- 设计师可以填写、修改和确认 LLM 生成内容；
- 每个图片计划项创建一个图片任务和一个套图卡片；
- 首次批量生成严格执行 `N 个任务 → N 张首图`；
- 单卡修改提示词后，每次只生成一张新图；
- 历史版本保留、并排对比、重新选择当前版本/终版；
- 允许在已有方案中新增卡片，不重生已有卡片；
- 失败任务保留错误原因并支持重试；
- PostgreSQL 保存业务、提示词、Chunk 快照、模型请求摘要、状态和对象关系；
- MinIO 保存原图、缩略图、白底图、过程图、图片版本和终版对象；
- 使用 `.env` 中已配置的生图模型连接，不在代码中写入密钥。

### 2.2 首版不实现

- 移动端；
- 登录页和权限细分，不作为首版工作台验收阻塞项；
- 数据中台上传、商品资料维护、清洗、审核和 RAG 入库；
- PicAgent 修改 RAG 事实或 Chunk；
- 全能模式、电商模式、拆页、视频、多配多、多配一、SKU 套装、替换等其他模式的正式功能；
- 多人实时协同和复杂像素级画布编辑；
- 直接发布到电商平台。

当前上传只是最小功能测试入口。后续接入数据中台和清洗平台时，输入来源替换为审核后的图库，另行建立 PRD，不改变本工作台的版本追溯模型。

## 3. 用户与核心概念

### 3.1 用户

首版以设计师工作流为中心。登录和权限暂不展开，开发环境可直接进入工作台；正式权限在后续 PRD 中定义。

### 3.2 核心对象

| 对象 | 定义 |
|---|---|
| 套图方案 | 一次套图生产记录，包含输入图、白底图、模板、Chunk、图片计划和卡片 |
| 任务输入图 | 设计师当前上传的原始实拍图，最多六张 |
| 精修底图版本 | 针对一张输入图生成的白底精修结果；一张原图可以有多个历史版本 |
| 参考资料快照 | 设计师勾选的 Chunk 在本次 LLM 请求中的冻结内容 |
| 套图图片计划 | LLM 输出的结构化图片任务数组；每个计划项可创建一张卡片 |
| 套图卡片 | 一个图片任务的编辑和生成界面投影 |
| 图片版本 | 一次成功生图结果，不覆盖历史结果 |
| 生成尝试 | 一次生图调用的成功、失败或重试记录 |

## 4. 核心业务规则

### 4.1 输入图和白底精修

1. 每个套图方案最多六张输入图，至少一张才能开始后续流程。
2. 输入图按上传顺序保存，顶部缩略图横条展示。
3. 点击缩略图后，当前原图和对应白底图同步切换，其他图的状态不变。
4. 未点击生成按钮前，不调用白底精修模型。
5. 白底精修使用图生图接口，保留原图主体，目标为白底精修图。
6. 同一输入图再次生成时新增底图版本，不覆盖旧版本。
7. 每张输入图只有一个当前选中底图版本，但历史版本可以查看、对比和重新选择。

### 4.2 模板、Chunk 和 LLM

1. 模板按用途阶段隔离：底图精修、图片计划、单卡生图不得互相替换。
2. 前端提交模板版本 ID、动态字段、人工填写内容和选中的 Chunk ID。
3. 服务端冻结模板版本、动态输入、Chunk 的来源版本和实际内容快照。
4. Chunk 必须由设计师检索后明确勾选，不自动把全部召回结果送入 LLM。
5. LLM 使用现有 RAG 检索能力和项目 DashScope 配置。
6. LLM 默认只补全空字段，不覆盖设计师已经填写的内容。
7. 设计师可以修改 LLM 输出，修改后的内容进入图片计划快照。
8. 资料不足时返回需人工补充，不得虚构产品事实。
9. 必填项或计划 Schema 校验失败时，不能开始创作。

### 4.3 卡片与生成

1. 一个计划项对应一个图片任务和一张卡片，使用稳定 ID。
2. 首次批量生成时，当前 N 个任务各创建一个结果槽位，得到 N 张首图，不生成四倍候选。
3. 单卡精修时，每次只创建一个结果槽位和一张新图。
4. 新增卡片是独立图片任务，追加到当前方案，不修改已有计划项，不触发已有卡片重生。
5. 新增卡片首次生成同样只生成一张图，后续修改提示词仍一次生成一张。
6. 生图成功后创建不可变图片版本；失败只保存失败尝试，不创建伪造图片版本。
7. 失败可以重试，每次重试追加新的生成尝试。
8. 卡片归档而不是物理删除，图片、提示词和审计记录保留。

## 5. 页面与交互

### 5.1 工作台首页

首页采用“输入图对比 + 计划配置”的主结构：

- 方案名称、保存状态、最近更新时间；
- 顶部 1–6 张原图缩略图横条；
- 原图和对应白底精修图的对比区域；
- 白底模板、动态输入、生成白底图按钮和底图版本历史；
- 图片计划模板选择；
- 模板动态输入区；
- RAG Chunk 搜索、结果列表、勾选和已选资料区；
- LLM 生成计划按钮；
- 计划预览和人工编辑区；
- 开始创作按钮；
- 最近项目列表，显示方案名称、输入图数量、卡片数量、状态和更新时间。

### 5.2 创作板

- 卡片网格或列表展示图片用途、提示词摘要、当前图、状态和版本数；
- 批量生成按钮显示当前任务数 N 和预计首图数 N；
- 每张卡片提供单卡生成、打开精修、版本对比、重试和归档；
- 新增卡片表单包含用途、画面说明、提示词和排序位置；
- 卡片状态包括：待补全、待生成、生成中、已生成、精修中、失败、已归档；
- 刷新后从 PostgreSQL 恢复真实状态。

### 5.3 单卡精修

- 只修改当前卡片的提示词和允许的生成参数；
- 每次点击生成只产生一张新图；
- 当前版本和历史版本支持两版并排对比；
- 可以将历史版本重新设为当前图或终版图；
- 过程图只读预览、放大，不提供像素级编辑；
- 每个版本可以查看提示词、模板、Chunk、模型和时间快照。

## 6. 生图模型配置

首版使用项目 `.env` 已配置的模型连接：

| 配置项 | 用途 |
|---|---|
| `IMAGE_GENERATION_BASE_URL` | 生图服务地址 |
| `IMAGE_GENERATION_API_KEY` | 服务端调用密钥，仅服务端读取 |
| `IMAGE_GENERATION_MODEL` | 模型名，首版为 `gpt-image-2` |

调用约束：

- 文生图使用 `/v1/images/generations`；
- 图生图/白底精修使用 `/v1/images/edits`；
- `model` 使用环境变量值；
- `n` 固定为 `1`；
- 优先使用 `response_format=b64_json`，服务端收到后立即写入 MinIO；
- 不把 API Key、Authorization、临时图片 URL 写入前端、数据库业务快照或日志；
- 生图 provider 通过稳定适配器封装，业务层不依赖供应商响应字段。

图片生成输入必须包含：

- 冻结的提示词版本；
- 当前任务输入图或已选择白底底图；
- 模板版本；
- 参考资料和人工输入快照；
- 尺寸、比例、质量和模型配置；
- 请求 ID、尝试 ID 和任务 ID。

## 7. 数据存储

### 7.1 PostgreSQL

使用服务器 PostgreSQL，创建 PicAgent 套图工作台专属数据库或专属 schema，不写入 RAG 业务表。

至少保存以下数据：

- 套图方案、状态和最近项目索引；
- 输入图元数据、哈希、尺寸、顺序和对象键；
- 白底底图版本、当前选择和生成记录；
- 模板版本、动态输入和提示词版本；
- Chunk 稳定来源 ID、上游版本和实际内容快照；
- LLM 请求、输出、Schema 版本和图片计划；
- 图片任务/卡片、排序、归档状态和提示词草稿；
- 生成批次、结果槽位、尝试、模型配置、错误和重试关系；
- 图片版本、当前版本/终版选择和历史关系；
- 关键操作审计记录。

历史版本、失败尝试和归档卡片不物理删除。

### 7.2 MinIO

使用服务器 MinIO 的 PicAgent 专属 Bucket。对象不原地覆盖，PG 保存对象键、哈希、尺寸、mime 和业务关系。

推荐对象键：

```text
suites/{suiteId}/inputs/{inputId}/original
suites/{suiteId}/inputs/{inputId}/thumb
suites/{suiteId}/inputs/{inputId}/base/{baseVersionId}/process/{step}.png
suites/{suiteId}/inputs/{inputId}/base/{baseVersionId}/final.png
suites/{suiteId}/tasks/{taskId}/versions/{versionId}/process/{step}.png
suites/{suiteId}/tasks/{taskId}/versions/{versionId}/final.png
```

服务端生成短期访问地址或通过 API 代理访问，前端不保存永久对象地址。

## 8. 最小 API 契约

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/suites` | 创建套图方案 |
| `GET` | `/api/suites` | 最近项目 |
| `GET` | `/api/suites/:suiteId` | 恢复工作台 |
| `POST` | `/api/suites/:suiteId/input-images` | 上传输入图 |
| `POST` | `/api/suites/:suiteId/base-generation` | 生成白底精修图 |
| `GET` | `/api/suites/:suiteId/templates?stage=...` | 获取阶段模板 |
| `POST` | `/api/rag/chunks/search` | 检索 Chunk |
| `POST` | `/api/suites/:suiteId/plan` | LLM 生成图片计划 |
| `PATCH` | `/api/suites/:suiteId/plan` | 保存人工修订计划 |
| `POST` | `/api/suites/:suiteId/tasks` | 新增卡片 |
| `PATCH` | `/api/suite-tasks/:taskId` | 修改卡片草稿或归档 |
| `POST` | `/api/suites/:suiteId/generation` | 批量首图生成，N 个任务对应 N 张图 |
| `POST` | `/api/suite-tasks/:taskId/generation` | 单卡生成一张图 |
| `GET` | `/api/suite-tasks/:taskId/versions` | 查询历史版本 |
| `POST` | `/api/suite-tasks/:taskId/versions/:versionId/select` | 选择当前版本/终版 |
| `POST` | `/api/generation-attempts/:attemptId/retry` | 重试失败尝试 |

具体接口命名可在技术设计阶段统一，但不能改变本 PRD 的业务语义。

## 9. 状态流

```text
草稿方案
  -> 输入图已保存
  -> 底图待生成 -> 底图生成中 -> 底图已生成 / 底图失败
  -> 计划待补全 -> 计划生成中 -> 计划已生成
  -> 卡片待生成 -> 批量生成中 -> 部分成功 / 全部成功
  -> 单卡精修中 -> 新版本生成中 -> 当前版本已选择
```

状态以服务端 PostgreSQL 为准。刷新页面、关闭页面或重新打开方案，不得丢失任务状态。

## 10. 错误与审计

- 输入图超过六张：拒绝上传并明确显示上限；
- 没有输入图：禁止开始创作；
- 模板阶段不匹配：拒绝提交；
- 必填动态字段为空：禁止调用 LLM 或生图；
- Chunk 不存在或快照失败：阻止本次计划生成；
- LLM 输出 Schema 失败：不创建图片任务，保存失败原因；
- 生图超时、供应商失败或返回无效图片：保存失败尝试并允许重试；
- MinIO 保存失败：图片版本不标记成功；
- 所有上传、计划生成、批量生成、单卡生成、新增卡片、版本选择、归档和重试都保存审计记录；
- 日志和错误响应不得泄露 API Key、Cookie、Authorization、临时签名地址或生产数据。

## 11. 验收标准

### 11.1 首页和底图

- 能上传 1–6 张图片并正确展示缩略图顺序；
- 点击缩略图后，原图和对应白底图同步切换；
- 未点击生成前没有生图调用；
- 同一原图连续生成两次，两个底图版本都能查看和切换；
- 刷新后输入图、底图版本和当前选择恢复。

### 11.2 计划和资料

- 模板按阶段过滤；
- 只有设计师勾选的 Chunk 进入 LLM；
- LLM 能生成结构化图片计划；
- 设计师手填内容不会被默认覆盖；
- 必填项缺失或 Schema 失败时不能开始创作；
- PG 能查到模板、Chunk 快照、LLM 输入/输出和计划版本。

### 11.3 卡片和版本

- 当前有 N 个任务时，首次批量生成得到 N 个结果槽位和 N 张首图；
- 单卡每次生成只新增一张图片；
- 新增卡片只增加新任务，已有卡片图片数量不变；
- 历史版本可以两版对比并重新选择；
- 失败、重试和刷新恢复均可验证。

### 11.4 数据和安全

- 原图、白底图、过程图、图片版本和终版对象写入服务器 MinIO；
- PG 保存对象键、哈希、模型、提示词、状态和业务关系；
- PicAgent 不写入 RAG 业务数据；
- `.env`、密钥和临时 URL 不进入 Git、前端 bundle 或日志。

## 12. 开发顺序

1. 初始化本独立项目的前后端目录和服务器配置读取；
2. 创建 PostgreSQL 迁移和 MinIO 对象存储适配；
3. 实现 `gpt-image-2` provider 和最小真实生图链路；
4. 实现套图首页：上传、缩略图切换、白底精修和版本选择；
5. 实现模板、Chunk、DashScope LLM 计划生成；
6. 实现创作板、N→N 首图、单卡生成、新增卡片和历史版本；
7. 做桌面浏览器验证、刷新恢复、失败重试和数据库/对象存储追溯验证。

登录权限、数据中台清洗链路和其他模式在本 PRD 完成后另行立项。
